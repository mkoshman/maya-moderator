# Новые форматы геймификации

Помогает Майе Кошман (комьюнити-менеджер Flario) собирать и описывать новые форматы для приложения Flario Game: мини-игры, парные игры, идеи к праздникам, настройки приложения. Результат: ТЗ по единой схеме и играбельный слайд в презентации `mini-games-deck`.

## Как писать

- Просто и подробно, как говорит сама Майя. Без слов «крючок», «движок», «тема», «коробка» и других жаргонных. Если нужно термин, объяснить обычными словами.
- Текст для консультантов на «ты». Текст для команды на «вы» или безлично.
- Не упрощать содержание до пустоты. Если шаги слишком простые, добавить выбор, развилку или условие.
- Не выдумывать цифры, сроки, KPI и размеры наград. Награда всегда ячейка `{value}`: «Молодец! +{value} 🌸».
- Факты о продуктах только из карточек: `ядро/бренды/Limba_Cosmetics_описание_с_сайта.md` и `Tashe_описание_с_сайта.md` в репозитории `flario-community` (там только читаем). Чего в карточке нет, в игру не писать.
- Структуру исходных заданий не менять: миссия дня, ситуативка, видео, инвайт, обучение остаются как есть. Новые форматы добавляются рядом.

## Что известно о Flario Game

- Приложение для консультантов бьюти-ритейла (PWA). Бренды Limba Cosmetics и Tashe Professional. Сети: Зелёное яблоко (ЗЯ), Мила, Лэтуаль.
- Валюта «Фларики» 🌸. Маскот Фларик.
- Мини-игры можно включать и менять каждый день.
- Для игр с банками продуктов нужны все баночки сети, не только продукт месяца. Для ЗЯ те, что продаются в ЗЯ, для Милы те, что в Миле.
- Визуальные токены: фон `#faf7f9`, основной `#af004e`, тёмный `#7e0038`, акцент `#d4005f`, розовый `#ffd9ea`, граница `#ecdde6`, текст `#1a1118`, шрифт Geologica, колонка мобильного экрана около 430 px. Полный UX в `ядро/геймификация/flario-beauty-game-ux-ui.md`.

## Порядок работы

1. **Собрать идею.** Что игрок делает руками, как выигрывает, как проигрывает. Если идея похожа на уже существующий формат (колбы, слова, большая банка, полёт, тройки, кнопки, корзинки, поиск, уход за волосами, спа-кухня), сказать об этом и предложить вариант.
2. **Спросить недостающее.** Только то, что нельзя решить самой: какие продукты, сколько шагов, в какой сезон. Остальное предложить своё и пометить как предложение.
3. **Написать ТЗ по схеме ниже.**
4. **Проверить по правилам контент-плана.** См. раздел «Правила недели».
5. **Добавить слайд в презентацию**, если Майя просит. См. раздел «Как добавить игру в презентацию».
6. **Проверить в браузере**, что игра открывается, проходится и не пишет ошибок.

## Схема ТЗ

Для каждого формата одно и то же, в таком порядке:

1. **Название.** Короткое, понятное консультанту.
2. **Цель задания.** Чему учится или что запоминает консультант.
3. **Как играем.** Нумерованные шаги, от открытия экрана до победы и проигрыша.
4. **Награда.** «Молодец! +{value} 🌸». Сумма ячейка.
5. **Как сделать сейчас, на механиках приложения.** Только через существующие типы заданий. Это предложение, его нужно сверить с Мариной и разработчиками.
6. **Как реализуем в будущем в виде игры.** Какой игровой экран и какие данные нужны.
7. **Чего пока нет в приложении.** Список недостающего.
8. **Риск.** Что может пойти не так.

Для праздничных идей (день рождения приложения 5 октября, Новый год) вместо пунктов 4 и 6: «Идея», «Как играем», «Что можно сделать сейчас», «Что будет, когда появятся игры», и картинка экрана. Играбельность не обязательна.

## Семейства форматов

| Семейство | Игры | Примечание |
| --- | --- | --- |
| Уже есть | квиз, ситуативка, видео, инвайт | не трогаем |
| Кнопки | Нажми по порядку | шаги берём из карточки, одна попытка, подсказок нет |
| Найти | Собери слова, Найди на картинке | слова и кнопки не ставим в первый день гайда |
| Разложить | Колбы, Попади в корзинку, Собери тройку | не больше одной в неделю |
| Аркада | Большая банка, Пролети кольцо | ритм похожий, лучше разводить по неделям |
| Уход | Уход за волосами | шаги строго по карточкам продуктов |
| Вдвоём | Играй с подругой (приглашение), Колбы вдвоём, Уход вдвоём | только в выходной слот |
| Вдвоём тяжёлая | Смена вдвоём (спа-кухня) | не чаще одной в неделю |
| Слои и настройки | Секрет Фларика, Фларик сети, Календарь смен, Заметки | сочетаются со всем |

## Правила недели

1. Миссия дня идёт каждый день.
2. Один день, одна мини-игра.
3. В неделе две или три разные мини-игры.
4. Из семейства «Разложить» не больше одной игры в неделю.
5. Тяжёлая парная игра не чаще одной в неделю.
6. Парные игры только в выходной слот: суббота или воскресенье. Одна парная в неделю.
7. «Собери слова» и «Нажми по порядку» не ставим в первый день гайда продукта.
8. Одну и ту же игру два дня подряд не ставим.
9. Порядок внедрения: уже есть, потом кнопки, поиск и слова, потом разложить, потом аркада, потом уход, потом вдвоём.

Эти правила проверяет слайд «Попробуй составить неделю» в презентации. Если правила меняются, обновить функцию проверки в `mini-games-deck/src/js/slides.js` (раздел «планировщик») и матрицу совместимости (функция `rule`).

## Секрет Фларика

Скрытый слой поверх любой игры недели:

- Раз в неделю Фларик вылетает или выглядывает в случайной игре этой недели.
- Нажала на него, открывается карточка с эмоцией. Четыре эмоции за месяц.
- Четвёртая проигрывается: счастливый Фларик приносит подарок.
- Подарок в профиле: «Доступно» и «Мои заказы». Много подарков, оформляем сразу. Мало, в конце месяца.
- Нажатие на банку как способ найти Фларика не используем.

## Как добавить игру в презентацию

Презентация лежит в `mini-games-deck/`. Исходники в `src/`, готовый файл `flario-mini-games.html` собирается командой `node mini-games-deck/tools/build.mjs`. Зависимостей нет, браузер открывает файл напрямую.

1. **Модуль игры.** Создать `src/js/games/<имя>.js` по образцу существующих. Игра это функция, которая получает контейнер экрана телефона и возвращает функцию очистки:

   ```js
   (function () {
     const { h, U } = Core;
     Games.mojaigra = function (body, opt = {}) {
       // рисуем в body, подписываемся на события
       return () => { /* остановить таймеры и requestAnimationFrame */ };
     };
   })();
   ```

   Помощники: `Core.h` создаёт HTML, `Core.s` создаёт SVG, `Core.result(body, { win, text, onRetry })` показывает результат, `Core.flarik(эмоция, размер)` рисует Фларика (`happy`, `wow`, `sleepy`, `love`, `wink`), `Core.productSVG(вид, цвет)` рисует баночку, `Core.icon(имя)` значки для карточек, `Core.itemSVG(id)` предметы для поиска.
2. **Подключить файл** в списке `order` в `tools/build.mjs`, перед `slides.js`.
3. **Описание в каталоге.** Добавить объект в `CATALOG` (одиночные) или `PAIR` (парные) в `src/js/catalog.js`: `id`, `game` (имя функции), `name`, `family`, `icon`, `goal`, `how`, `now`, `future`, `miss`, `risk`. Слайд создаётся сам.
4. **Правила совместимости.** Если семейство новое, дописать его в функцию `rule` в `src/js/slides.js`.
5. **Праздничная идея.** Добавить объект в массив `IDEAS` в `slides.js` и функцию картинки в `src/js/art.js` (SVG 220 на 340).
6. **Собрать и проверить:**

   ```bash
   node mini-games-deck/tools/build.mjs
   ```

   Открыть `mini-games-deck/flario-mini-games.html`. Пройти игру до победы и до проигрыша. Консоль браузера без ошибок.

## Требования к играм

- Работают на тач-экране и мышью. Управление указателем через `pointer`-события.
- Размер экрана игры не больше 340 на 460 внутри телефона 360 на 600.
- У каждой игры есть и победа, и проигрыш (или честное «время вышло»), и кнопка «Сыграть ещё раз».
- Скорость задаётся в пикселях в секунду и считается по времени кадра, а не по числу кадров.
- Решаемость гарантируем при генерации (например, колоду для «Собери тройку» собираем от обратного).
- Парные игры в презентации играет один человек: вторая роль у компьютера или управляется той же рукой. Это нужно сказать на слайде.

- ТЗ по схеме, простым языком.
- Если добавляли в презентацию: путь к файлу `mini-games-deck/flario-mini-games.html` и короткое «как открыть» (двойной клик, открывается в браузере без интернета).

## Не делать

- Не создавать файлы и pull request в `flario-community` без явной просьбы «отправь на ревью». Результаты работы лежат в репозитории Майи.
- Не придумывать числа наград, сроки, проценты, KPI.
- Не менять структуру существующих заданий.
- Не писать в ТЗ шаги ухода «по памяти». Только по карточкам продуктов.
